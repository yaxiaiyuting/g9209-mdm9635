# 恢复步骤：把手机从 boot-AE-diag 刷回已知可用的 boot-AD

## 已知事实
- 刷入的 `/data/block/sda8`（BOOT 分区）内容：`mdm-work/boot-AE-diag.img`
  - md5 `f00077906e240714e899ee0f2fbda5c1`，29,360,128 B
  - 结构校验通过：`ANDROID!` 头、5 条 DTB 记录全部自洽、内核含 `MDM-DIAG`
  - BOOT 分区 7168 块（3.5 MiB），镜像 28 MiB → **不越界**
- 刷入前备份（**在手机内部存储**）：`/data/local/tmp/diag/boot-before-AE.img`
  - md5 `5e575b6a0eb83eb5bd1d731349798d9d` = 已知可用的 **boot-AD**

## 主机上的可用镜像（都在 `baseband-study/mdm-work/`）
| 文件 | md5 | 说明 |
|---|---|---|
| `boot-AD-reqleft.img` | `5e575b6a0eb83eb5bd1d731349798d9d` | ★ 刷入 AE 之前设备上跑的版本，**已知可用** |
| `boot-AE-diag.img` | `f00077906e240714e899ee0f2fbda5c1` | 当前刷入的诊断版 |
| `../safety/boot-current-20261002.img` | `ddb6120cf9df0ffebbf438e10c7518b5` | 更早的备份（count=2 的旧 DTB 布局） |

## 恢复方法（按优先级）

### 方法 1：能进 TWRP（推荐，最快）
```bash
adb push mdm-work/boot-AD-reqleft.img /tmp/boot-AD.img
adb shell 'dd if=/tmp/boot-AD.img of=/dev/block/sda8 && sync'
```
或用 TWRP 的 Install → Install Image → 选 boot 分区。

### 方法 2：能进系统（adb 可用）
```bash
adb push mdm-work/boot-AD-reqleft.img /data/local/tmp/boot-AD.img
adb shell 'dd if=/data/local/tmp/boot-AD.img of=/dev/block/sda8 && sync'
# 或直接用手机内已有的备份：
adb shell 'dd if=/data/local/tmp/diag/boot-before-AE.img of=/dev/block/sda8 && sync'
```

### 方法 3：只能进 Download 模式（Odin / heimdall）
先把镜像包成 Odin 可用的 tar：
```bash
cd baseband-study
cp mdm-work/boot-AD-reqleft.img boot.img
tar -H ustar -cf boot-AD.tar boot.img && md5sum -t boot-AD.tar >> boot-AD.tar && mv boot-AD.tar boot-AD.tar.md5
# heimdall（Linux）：
heimdall flash --BOOT boot.img
```

### 方法 4：强制关机再开机
长按电源键 10–20 秒强制断电，等 10 秒，再开机。
（若只是 OTG/线缆掉了导致 adb 中断，这一步就够。）

## 注意
- `/dev/block/sda8` = BOOT 分区（`by-name/BOOT` 符号链接）。
- 刷写后必须 `sync`。
- 刷完 boot-AD 后，设备应恢复到"能正常启动 + adb 可用"的状态。
