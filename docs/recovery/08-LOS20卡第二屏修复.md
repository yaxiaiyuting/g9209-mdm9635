# LOS 20 卡第二屏（system_server 崩溃循环）—— 根因与修复

## 症状
刷回 LOS 20 后卡在开机动画（第二屏），`init.svc.bootanim=running` 永不结束，
`sys.boot_completed` 始终为空。`system_server` 每约 12 秒崩溃重启一次。

## 根因
```
java.lang.RuntimeException: Failed to boot service com.android.server.trust.TrustManagerService:
    onBootPhase threw an exception during phase 500
  at com.android.server.SystemServiceManager.startBootPhase
  at com.android.server.SystemServer.startOtherServices
Caused by: android.database.sqlite.SQLiteException:
    Can't downgrade database from version 3 to 2
  at android.database.sqlite.SQLiteOpenHelper.onDowngrade
  at com.android.server.locksettings.LockSettingsStorage.writeKeyValue
  at com.android.server.trust.TrustManagerService.initializeKnownAgents
```

**`/data/system/locksettings.db` 是 SQLite 版本 3**（原厂 Android 7.0 开机时升级上去的），
而 **LOS 20 只认版本 2** → 无法降级 → `system_server` 崩溃循环 → 卡第二屏。

> 这是"先用原厂系统、再刷回 LOS 20"这个来回造成的典型数据版本回退问题。

## 修复（已验证有效）
在 TWRP 里挂载 USERDATA，**删除**（先备份）：
```
/data/system/locksettings.db
/data/system/locksettings.db-journal
/data/system/locksettings.db-shm
/data/system/locksettings.db-wal
```
然后重启 → **正常启动**（`boot=1`、`bootanim=stopped`）。

> 代价：只丢锁屏设置，**不丢应用数据**。备份放在 `/data/local/tmp/lockbk/`。

## 顺带修掉的另一个坑：cbd 钩子
之前 `/system/vendor/bin/cbd` 被换成我写的实验钩子（每次 spawn worker）。
LOS 20 首启清理过 `/data`，worker 不在了 → 钩子反复 spawn 失败 → init 判定
core service 失败。**已换成"常驻不退出"的惰性版本**（不再 spawn）：
```sh
#!/system/bin/sh
while true; do sleep 3600; done
```
> 教训：`cbd` 的替身**必须常驻**，且**默认不要自动跑实验流程**。

## 复发预防
- 若再从原厂系统刷回 LOS 20（或反向），**先删 `/data/system/locksettings.db*`**
- 更彻底：跨 Android 大版本切换时直接 `wipe /data`（有备份时最省事）
