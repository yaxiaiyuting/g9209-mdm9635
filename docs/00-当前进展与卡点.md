## 一、必须修正原文档的三处结论

### 1.1 `mode=2` 不是"命令模式"（原文档 §3.5 / §7 的核心判断错了）

按[高通 Sahara 协议规范](https://lore-kernel.gnuweeb.org/linux-arm-msm/ab548ca1-c758-4096-b6aa-bce886fd904f@oss.qualcomm.com/T/#u)：

| mode | 含义 |
|---|---|
| 0 | IMAGE_TX_PENDING（还有镜像要传） |
| **1** | **IMAGE_TX_COMPLETE（镜像已全部传完）** |
| 2 | MEMORY_DEBUG（内存转储） |
| **3** | **COMMAND（命令模式）** |

原文档把实测到的 `HELLO mode=2` 记成"命令模式"，由此把剩余工作定为"实现命令模式"。
**方向错了**：我们实测拿到的是 **`HELLO mode=1`**，即 modem 自己宣告"镜像已收齐"，Sahara 协议层本来就已经完成。
不需要实现命令模式。

### 1.2 "USB 停在 05c6:9008" 不是故障

子代理穷尽搜索 9 个 `.mbn` + 12MB DDRCS0：`0x9048/0x904C/0x9075` 这些 AMSS 阶段 PID **不在固件里**；
唯一存在的 VID:PID 就是 `05c6:9008`，且它在 **`sbl1.mbn`** 里（偏移 `0x2a13c`）。
但**内核 `ks_bridge.c:576-586` 的 `ksb_usb_ids[]` 明确认这些 PID**（`USB_DEVICE_INTERFACE_NUMBER(0x5c6,0x9048,2)` → `efs_hsic_dev`）。
→ 结论：AMSS 起来后**应当**用这些 PID 重新枚举出一个复合设备（interface 2 绑定成 `/dev/efs_hsic_bridge`）。
`9008` 只是 PBL 阶段的身份，**它不会自己变成 9048，必须由 AP 侧动作触发重新枚举**。

### 1.3 "modem 收完固件不执行" 是错的 —— **modem 确实执行了**

实测 dmesg（loader v40，已移除一切自我复位逻辑）：
```
[ 89.822] ext-mdm: Signaling request engine for images
[  ~90  ] 12 个镜像全部 END_IMAGE_TX status=0（21 MB/s，20 秒喂完 67MB）
[101.203] ext-mdm: status = 1: mdm is now ready     ← ★ AMSS 起来了（原文档从未见到这一行）
```

## 二、真正卡住的原因（已定位并修复 3 项）

### 2.1 必须有一个进程常驻持有 ESOC request engine
内核把 modem 请求投进 req fifo，**只有注册为 request engine 的进程**能取走（`ESOC_WAIT_FOR_REQ`）。
无人持有 → PBL 永远不发 Sahara HELLO（表现为端口打开却零数据 + `XactErr len 0/16384`）。
这是原文档完全没意识到的前提。
→ 工具：`tools/esoc_reqeng.c`（常驻；父进程持 req engine，fork 子进程抽干 evt fifo）。

### 2.2 `ESOC_BOOT_DONE` 只能由用户态发，内核从不发
`drivers/esoc/esoc-mdm-4x.c:563` 的 `case ESOC_BOOT_DONE: esoc_clink_evt_notify(ESOC_RUN_STATE, esoc);`
是 `ESOC_RUN_STATE` 的**唯一**来源；它到达 `esoc-mdm-drv.c:65` 才 `complete(&boot_done)`。
不发 → `powerup` 永久阻塞、`subsys0/state` 永远 OFFLINE。
原厂 `mdm_helper` 里有这段（strings 可见 `Failed to send ESOC_BOOT_DONE notification`）。
→ 已在 `tools/esoc_reqeng.c` 的 boot_done watcher / `tools/mdm_runtime_handshake.c` 中实现。

### 2.3 `powerup` 工具退出会关 fd → 内核把 modem 打掉
`subsys_device_close()`（`arch/arm64/mach-exynos/subsystem_restart.c:909`）→ `subsystem_put()`
→ 引用计数归零 → `mdm_subsys_shutdown()` → `ESOC_PWR_OFF`。
实测：`powerup` 一退出，紧接着就是 `Graceful shutdown fail, ret = -19` + `Doing a hard reset`。
→ 工具：`tools/esoc_pwron_hold.c`（上电后**常驻持 fd**）。

## 三、当前唯一卡点：AMSS 不重新枚举

原厂 `mdm_helper` 在 modem 报 ready 之后还有 **4 步**（反汇编 + [同族机型原厂源码](https://blog.csdn.net/hongzg1982/article/details/54884883) 双向确认）：

## 7.3 ★★★ 真正的线索：`AP2MDM_HSIC_READY` 全程为 lo

上面每一行采样里 `AP2MDM_HSIC_R=lo` —— 即 **`AP2MDM_HSIC_READY`（gpio-135）从未被拉高**。

这与 modem 固件里的证据吻合（`apps.mbn`，构建路径 `ZEROFLTE_CHN_CTC`，正是本机）：
```
SS_Hsic_host_ready_Raising_Signal_Isr / Falling_Signal_Isr
SS_drive_Device_Ready_Gpio
 - Rearm Timer : is_host_ready_recvd=%d, is_hwgpio_timer_started=%d
 - HSIC DEVICE_READY Setting HIGH, USB PHY ON : ready=%d
 - make the HSIC connect signal
```
→ **AMSS 把"打开自己 USB PHY / 拉起 DEVICE_READY / 发出 HSIC connect"门控在
"收到 AP 的 HOST_READY（= `AP2MDM_HSIC_READY`）上升沿"上**，并用一个会 Rearm 的定时器跟踪。
收不到 → 不开自己的 USB → 不重新枚举 → 约 11 秒后自复位。**这与实测现象完全一致。**

**已排除"是代码路径没被调用"以外的可能**：
- `mdm_set_hsic_ready()`（`esoc-mdm-4x.c:783`）实现正确：`gpio=0 → msleep(10) → gpio=1`，**会拉高**
- 该 GPIO 已被驱动 `gpio_request` 成功（sysfs `export` 被拒绝 = 被驱动占用），不是"无法控制"
- DT 正确：`qcom,ap2mdm-hsic-ready-gpio = <&gpf2 3 0x1>` = gpio-135

因此下一步就是**确认 `mdm_set_hsic_ready()` 到底有没有被调用、被调用时 gpio 实际值是多少**
（已加 3 条 `[MDM-DIAG]` printk，正在重编内核）。

## 7.4 原厂 `mdm_helper` 逆向的最终结论（子代理报告 `FINDINGS-vendor-sequence.md`）

- `peripheral_reset()` = **就是** `写 unbind → usleep(10000) → 写 bind`，**没有任何额外动作**
  （只碰 `/sys/bus/platform/drivers/s5p-ehci/{unbind,bind}`，内容 `"15510000.usb"`）
- 原厂 **不在等任何 GPIO**（整个 binary 里没有 gpio/usb2phy/devicerdy/hostwake 字符串）
- `WaitForCOMport` 单位是 **0.5 秒**：`75` = **37.5 秒**
- **modem ready 之后原厂 AP 侧什么都不做** —— `mdm9k_monitor()` 阻塞在 `ESOC_WAIT_FOR_REQ`
- ★ 我们缺 `MODE_BOOT` 的链路建立：原厂在 Sahara 前先
  `unbind → ESOC_NOTIFY(4=IMG_XFER_RETRY)（内核据此 mdm->init=1 + 软复位）→ WAIT_FOR_REQ → 500ms → bind`
- ★ `ESOC_IMG_XFER_DONE`(1) 应在 Sahara **之后**发（我们现在提前发了）
- efs 桥等 15s 太短（应 37.5s），且**失败就不该发 BOOT_DONE**
- 本机 ks 参数：`ks -m -p /dev/efs_hsic_bridge -w /dev/block/modem/ -t -1 -l`（**没有** `-g`）
