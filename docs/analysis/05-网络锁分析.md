# 网络锁（SIM / 网络锁）分析

> 摘自 `基带可用性-可行性研究报告.md` §7，供参考。

### 7.1 已知证据
- **AP 侧（CSC）没有配 SIM 锁**：从 CSC 包 `cache.img → /recovery/sec_csc.zip → system/csc/customer.xml` 里读到
  ```xml
  <Security>
    <OneSIMLock>none</OneSIMLock>
  </Security>
  ```
  → **运营商定制层并没有启用 OneSIMLock**（这是三星 AP 侧网络锁的配置位）。所以"锁"不在 CSC 配置里。
- **锁逻辑在 modem 固件内部**：`QDSP6SW.MBN` 里有 `simlock_task_init`、`SIM_LOCK_INFOMATION`、`SIM_Lock`、`PERSO_STATE`、`PERSO_FEATURE`、`user_lock_state`、`user_lock_code`、`Sim_Lock_Or_Unsupported` —— 这是 Qualcomm 的 **PERSO（个人化）SIM-Lock** 机制（任何高通 modem 固件都带这套代码，**它的存在不等于锁被置位**）。
- **RIL 层有 CTC 特判**：原厂高通版 `libsec-ril.so` 里有 `broadcast -a com.samsung.intent.action.IsNotCTC`、"CDMA CardNoti NO SIM" 等 → 三星 RIL 会识别"插的不是 CTC 卡"并广播，说明**合约机的限制更可能是"机卡绑定"这一层**（见下）。
- **合约机的运营商 App 在 `/preload`**：`CTClient_V520`、`CTAccount_V30MNoIcon`、`CTC_iTing4G_V2.006_N`、`CTC_PIM_V3.0`、`ChinaUnionPay`。
- **bootloader 侧**：`sboot.bin` 有 `MDM SET : PREVENT DOWNLOAD . CASE:%d`、`MDM MODE. CAN'T DOWNLOAD.`、`Cannot download m9kefs3`（是否与合约状态相关**待确认**，见 §10）。
- **AP 侧 `/efs` 未见 lock 文件**（只有 `imei/ prov/ prov_data/ sec_efs/ FactoryApp/` 等），**没有 `nv_data.bin`**——因为 `nv_data.bin` 是 Shannon 的 NV 约定；这台机器的 modem NV 在 `m9kefs1/2` 里。
- **`m9kefs1/2/3` 的数据段是高熵**（头部 0x2C 字节 + `IMGEFS1$`/`IMGEFS2#`/`IMGEFSG$` 标记之后即不可读），**疑似加密/私有格式** → 纯离线定位并改锁位不现实。

### 7.1b 三种"锁"要分清楚（决定可行性）
| 类型 | 在哪 | 本机证据 | 本地能否解除 |
|---|---|---|---|
| A. AP 侧 SIM/网络锁（OneSIMLock / SP Lock） | 系统 CSC 配置 + framework | **`OneSIMLock=none`，未启用** | 无需解除 |
| B. Modem PERSO/网络锁 | modem NV（`m9kefs1/2`） | 固件含 PERSO 代码，**是否置位未知**（需 modem 起来后查 `PERSO_STATE`/`user_lock_state`） | 起来后可查；解锁需解锁码或改 NV（后者可行性低） |
| C. 运营商"机卡绑定"（合约机常见） | **运营商网络侧**（比对 IMEI↔SIM） | `/preload` 里一堆电信 App；RIL 有 `IsNotCTC` 广播 | **本地无法解除**（不是设备端能改的东西） |

> 换句话说：**先别假设"有网络锁"**。等 P4 完成、modem 能上报 SIM 状态后，用 `PERSO_STATE`/`user_lock_state` 判断到底是 A/B/C 哪一种；如果是 C，那属于与运营商的合约问题，技术手段无解。


### 7.2 可行路径（按推荐顺序）
1. **让 modem 跑起来后走"正当解锁"**：运营商（中国电信）解锁码 / Samsung 官方解锁流程；或通过 modem 的 **PERSO 解锁 AT/QMI 命令**（需正确的解锁码）。这是唯一"干净"的路径。
2. **modem 起来后读取锁状态**（`user_lock_state`/`PERSO_STATE` 可通过 AT/DIAG/QMI 查询），先搞清"到底是网络锁、机卡绑定还是 subsidy lock"，再决定手段。
3. **离线改 NV**：仅在能解析 `m9kefs` 格式（含校验/加密）时才可能，当前**判定为低可行性**。
4. **商用维修工具**（Z3X/UnlockTool 之类）：对"Exynos AP + 高通 MDM"这种非常规组合的支持情况需单独核实（R2 调研中）。

### 7.3 法律与风险（务必看）
- **明确违法**：修改 IMEI（中国《无线电管理条例》及工信部相关规定；情节严重可触及刑法）。本方案**不涉及也绝不建议**任何改 IMEI 操作。
- **解除自有设备的运营商网络锁**：一般属于**用户与运营商之间的合约/民事**范畴，不当然违法；但若设备非你所有、或用于规避他人合法权益，性质就不同。
- **技术风险**：`m9kefs1/2/3` 与 `EFS` 是**校准数据 + IMEI + 射频参数**所在，写坏会导致**永久无服务且无法自行恢复**（换字库也难）。**任何写操作前必须有多份冷备份**（你已有 TWRP 的 `EFS.img`、`m9kefs1/2/3.img`，建议再复制到异地）。
- 本报告只描述方向，不提供任何改 IMEI 或规避合法限制的具体步骤。
